## 1. Scope

This SOP applies to Windows desktop tools developed by Visual Studio / MFC, specifically:

- **NuvoISP (ISP Programming Tool)** – All release versions
- Any Nuvoton Windows MFC/Visual C++ desktop application
- All builds intended for distribution within the EU market

**Key principle**: SBOM should describe **what you actually ship**, not only the .sln source tree. The final .exe, required DLLs, and redistributable files must be placed in one `release/` drop folder for scanning.

---

## 2. SBOM Format

Use **SPDX 2.2** (or SPDX 3.0) generated by **Microsoft SBOM Tool**.

Supplementary formats:
- **CycloneDX v1.5** (JSON) for additional component-level detail and CVE scanning
- **vcpkg SPDX** if vcpkg is used

## 4. Procedure

### Step 1: Build the Official Release Package

Build the Release configuration in Visual Studio and verify the output is correct.

### Step 2: Prepare a Clean Release/Drop Folder

Copy **all shipping files** into a clean `release/` folder:

```
release/
├── NuvoISP.exe                    ← Main application
├── offline_isp_file_converter.exe ← Utility tool
├── GetChipInformation.dll         ← Required DLL
├── third_party_notice.txt         ← Third-party component list
├── HIDAPI-LICENSE-bsd.txt         ← Open-source license
└── HIDAPI-LICENSE.txt             ← License overview
```

**PowerShell example:**
```powershell
$releaseDir = "D:\build\NuvoISP\release"
$exeDir     = "D:\build\NuvoISP\Executable File"
$srcDir     = "D:\repo\NuvoISP"

New-Item -ItemType Directory -Path $releaseDir -Force
Copy-Item "$exeDir\NuvoISP.exe" $releaseDir
Copy-Item "$exeDir\offline_isp_file_converter.exe" $releaseDir
Copy-Item "$exeDir\GetChipInformation.dll" $releaseDir
Copy-Item "$srcDir\ThirdParty\hidapi\LICENSE.txt" "$releaseDir\HIDAPI-LICENSE.txt"
Copy-Item "$srcDir\ThirdParty\hidapi\LICENSE-bsd.txt" "$releaseDir\HIDAPI-LICENSE-bsd.txt"
```

### Step 3: Run Microsoft SBOM Tool

```powershell
sbom-tool generate `
  -b "D:\build\NuvoISP\release" `
  -bc "D:\repo\NuvoISP" `
  -pn "NuvoISP" `
  -pv "4.18" `
  -ps "Nuvoton Technology Corporation" `
  -nsb "https://www.nuvoton.com/sbom"
```

| Parameter | Meaning |
|-----------|---------|
| `-b` | **Build drop folder** – contains files to be shipped (hashed and added to SBOM) |
| `-bc` | **Build components/source folder** – scanned to detect components used to build the package |
| `-pn` | Package name |
| `-pv` | Package version |
| `-ps` | Package supplier |
| `-nsb` | Namespace base URI |

**For SPDX 3.0 output**, add:
```powershell
  -mi SPDX:3.0
```

**Output**: `release/_manifest/spdx_2.2/manifest.spdx.json`

> **Note**: For MFC projects without a package manager (no vcpkg/NuGet/conan), Microsoft SBOM Tool will detect 0 package-manager components. This is expected. The tool still provides value by:
> - Hashing all shipping files (SHA-256 + SHA-1)
> - Creating a valid SPDX document with proper metadata
> - Providing file-level integrity verification

### Step 4: If the Project Uses vcpkg — Collect vcpkg SBOM

If the MFC project uses vcpkg, vcpkg generates SPDX SBOM files for each installed package:

```
<installed_dir>/<triplet>/share/<package name>/vcpkg.spdx.json
```

Collect them:
```powershell
Get-ChildItem "D:\vcpkg_installed" -Recurse -Filter "vcpkg.spdx.json"
```

If CycloneDX format is needed, convert:
```powershell
cyclonedx convert `
  --input-file vcpkg.spdx.json `
  --input-format spdxjson `
  --output-format json `
  --output-file vcpkg.cdx.json
```

### Step 5: Supplement with Manual Third-Party Component Inventory

Since Microsoft SBOM Tool cannot detect vendored source code or pre-compiled binaries, maintain a **`third_party_notice.txt`** in the release folder listing all components:

| # | Component | Version | License | Source URL | Integration |
|---|-----------|---------|---------|-----------|-------------|
| 1 | HIDAPI | 0.8.0-rc1 | BSD-3-Clause | https://github.com/signal11/hidapi | Compiled from source |
| 2 | inipp | 1.0.0 | MIT | https://github.com/mcmtroffaes/inipp | Header-only |
| 3 | BleIO | (internal) | Proprietary - Nuvoton | Internal | Static library |
| 4 | GetChipInformation | (internal) | Proprietary - Nuvoton | Internal | DLL |
| 5 | MFC | 14.x | Microsoft EULA | Visual Studio | Static linking |
| 6 | VC++ Redistributable | 14.x | Microsoft EULA | Visual Studio | Runtime |

Additionally maintain a CycloneDX SBOM (`nuvoISP-sbom.cdx.json`) with detailed component metadata for CVE scanning.

### Step 6: Validate the Generated SBOM

```powershell
sbom-tool validate `
  -b "D:\build\NuvoISP\release" `
  -o "D:\build\NuvoISP\sbom-validation.json" `
  -mi SPDX:2.2
```

**Expected result**: `"Result": "Success"`, 0 validation errors.

### Step 7: Run CVE/Vulnerability Scan

Using the CycloneDX SBOM for component-level CVE matching:

```powershell
# Set proxy if behind corporate firewall
$env:HTTPS_PROXY = "http://proxy:port"

# Update vulnerability database
grype db update

# Scan
grype sbom:.\nuvoISP-sbom.cdx.json -o table
```

Additionally, manually check:
- **NVD**: https://nvd.nist.gov/ – search by component name + version
- **OSV**: https://osv.dev/ – search by package ecosystem
- **GitHub Advisory Database**: https://github.com/advisories

### Step 8: Run CRA Compliance Check (Supplementary)

```powershell
cd NuvoISP\sbom
powershell -ExecutionPolicy Bypass -File .\cra-compliance-check.ps1
```

This validates the CycloneDX SBOM for CRA-specific requirements (component completeness, license compliance, vulnerability handling readiness).

### Step 9: Archive Final SBOM Package

Assemble and archive the complete SBOM deliverable:

```
release/
├── NuvoISP.exe
├── offline_isp_file_converter.exe
├── GetChipInformation.dll
├── third_party_notice.txt
├── HIDAPI-LICENSE-bsd.txt
├── HIDAPI-LICENSE.txt
├── _manifest/
│   └── spdx_2.2/
│       ├── manifest.spdx.json         ← Microsoft SBOM Tool output (SPDX)
│       └── manifest.spdx.json.sha256
├── sbom-validation.json               ← Validation result
└── (optional) nuvoISP-sbom.cdx.json   ← CycloneDX SBOM for CVE scanning
```

## 5. Practical MFC Checklist

| Item | How to Handle |
|------|---------------|
| Final .exe / .dll / config files | Put in release folder, scan with Microsoft SBOM Tool |
| vcpkg packages (if any) | Keep `vcpkg.spdx.json` files |
| NuGet packages (if any) | Let Microsoft SBOM Tool scan the source/build component path |
| Manually copied third-party DLL/lib/source | Add to `third_party_notice.txt` with name/version/license/source URL |
| Microsoft VC++ Redistributable / MFC runtime | Record version used in release note or third-party list |
| CVE review | Run SCA/CVE review (Grype) based on detected third-party components |

---

## 6. When to Update the SBOM

| Trigger | Action |
|---------|--------|
| New third-party library added | Add to `third_party_notice.txt` + CycloneDX SBOM, re-run sbom-tool |
| Third-party library updated | Update version, re-check CVEs |
| Third-party library removed | Remove from inventory, re-run sbom-tool |
| Build toolchain changed | Update metadata, record new VC++ version |
| New release version | Update version, timestamp; re-run full pipeline |
| CVE reported for a component | Document in vulnerability tracking, update/patch component |

- [ ] Release drop folder contains all shipping files
- [ ] Microsoft SBOM Tool `generate` completed successfully
- [ ] Microsoft SBOM Tool `validate` shows "Success" with 0 errors
- [ ] `third_party_notice.txt` lists all components with name, version, license, source
- [ ] CycloneDX SBOM updated for CVE scanning
- [ ] CVE scan (Grype) completed — no unpatched critical/high CVEs
- [ ] HIDAPI version verified and up to date (or risk accepted/documented)
- [ ] Binary-only components (BleIO, GetChipInformation) provenance documented
- [ ] Vulnerability disclosure policy documented and accessible
- [ ] Secure update mechanism documented
- [ ] All license files included in release folder
- [ ] SBOM package archived with the release

## 10. Important: Difference vs. Buildroot SBOM Guide

The internal Buildroot guide's SBOM flow is:
```bash
make show-info | utils/generate-cyclonedx -o sbom.cdx.json
cat sbom.cdx.json | support/scripts/cve-check --nvd-path dl/buildroot-nvd/ > cve_results.json
```

That process is based on Buildroot package metadata and does **not** map to a Visual Studio/MFC project. MFC applications do not have Buildroot-style package metadata.

**For MFC, use instead:**
```
Microsoft SBOM Tool (for final Windows release artifacts)
+ vcpkg SPDX SBOM (if vcpkg is used)
+ manual third-party component inventory (for copied DLL/lib/source)
+ Grype SCA/CVE review (for open-source components)
```
